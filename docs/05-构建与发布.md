# 05 · 构建与发布

---

## 1. 依赖

| 需要 | 说明 |
|---|---|
| **Zig 0.14.1** | 自带 clang + mingw-w64 头文件与运行库。**不需要** MSVC、Windows SDK、MinGW |
| Windows x64 | 目标平台固定 `x86_64-windows-gnu` |
| PowerShell 5.1 | 只在跑 `build.ps1` / `installer.ps1` 时需要，系统自带 |

项目**没有**任何第三方构建依赖：`shared/minhook/` 是内嵌的源码，
其余全是 C 与一个 `.S` 汇编文件。

## 2. 编译

### 2.1 用 build.ps1（推荐）

```powershell
./hotkey/build.ps1   -Zig <zig.exe 路径> -OutDir ./hotkey/dist
./speedkey/build.ps1 -Zig <zig.exe 路径> -OutDir ./speedkey/dist
./pinattr/build.ps1  -Zig <zig.exe 路径> -OutDir ./pinattr/dist
./goldhand/build.ps1 -Zig <zig.exe 路径> -OutDir ./goldhand/dist
```

每个模块产出的是**同名文件** `d3d11.dll`。这是有意的：每个模块本身就是一个
完整的 d3d11 代理，单独放进游戏目录也能跑（卫星的输入钩已收归伞形，
所以实际部署时卫星用的是 `mod-*.dll` 这个名字，由伞形 `LoadLibraryW` 加载）。

### 2.2 手工命令

以伞形为例：

```bash
cd hotkey
export ZIG_GLOBAL_CACHE_DIR="$PWD/build/zgc" ZIG_LOCAL_CACHE_DIR="$PWD/build/zc"

zig cc -target x86_64-windows-gnu -O2 -Wall -Wextra -shared \
  -I src -I ../shared -I ../shared/minhook/include \
  src/waitkey.c ../shared/proxy.S src/proxy.def \
  ../shared/minhook/src/buffer.c ../shared/minhook/src/hook.c \
  ../shared/minhook/src/trampoline.c ../shared/minhook/src/hde/hde64.c \
  -ladvapi32 -luser32 -o dist/d3d11.dll
```

替换源文件即可编译其他模块：

| 模块 | 主源文件 | 额外链接 |
|---|---|---|
| hotkey | `waitkey.c` | — |
| speedkey | `speedkey.c` | `-lgdi32` |
| pinattr | `pinattr.c` | — |
| goldhand | `goldhand.c` | — |

### 2.3 四个必须知道的坑

**① `-I src` 不能省。**
`shared/rva_reloc.h` 内部 `#include "rva_anchors.h"`，而锚点表在每个模块自己的
`src/` 下。C 的引号包含只搜索「包含者所在目录」（即 `shared/`）加 `-I` 路径，
所以必须显式把模块的 `src/` 也加进搜索路径。

**② Zig 缓存目录必须显式指定。**

```bash
export ZIG_GLOBAL_CACHE_DIR="$PWD/build/zgc"
export ZIG_LOCAL_CACHE_DIR="$PWD/build/zc"
```

否则 Zig 会往 `%LOCALAPPDATA%\zig` 写缓存，在受限环境下报 `AccessDenied`。

**③ 首次编译很慢。** Zig 要从源码构建一份 mingw-w64 libc，几分钟起步；
之后就快了（缓存在 `build/zgc`）。

**④ 两次编译的 DLL 不是逐字节相同的。** Zig 会往 PE 头和 `.buildid`
段里写一段随机 build-id（约 20 字节）。`.text` / `.rdata` 等实际代码数据段
是完全一致的 —— 所以**不要拿整个文件的 SHA256 当版本判据**，
比对时要排除 `.buildid` 段（或直接比 `.text`）。

## 3. 主机侧测试（不启动游戏）

```bash
# 配置层单测
zig cc -target x86_64-windows-gnu -O2 -Wall -Wextra -I src -I ../shared \
  tests/hotkey-tests.c -o build/hotkey-tests.exe
./build/hotkey-tests.exe

# 代理冒烟：导出表是否 51 项、转发是否指对
zig cc -target x86_64-windows-gnu -O2 -Wall -Wextra tests/proxy-smoke.c -o build/proxy-smoke.exe
./build/proxy-smoke.exe dist/d3d11.dll build/scratch
```

验收标准：**`-Wall -Wextra` 下零告警**。

> 关于「不启动游戏就能验证」这件事：运行时重定位层的验证方式是把真实的
> `GameAssembly.dll` 用 `LoadLibraryExW(..., LOAD_LIBRARY_AS_IMAGE_RESOURCE)`
> 映射进进程 —— 它与挂钩时看到的 `ga` 在布局上同构，但**不执行任何游戏代码** ——
> 然后跑与出货 DLL **同一份** `rva_reloc.h` 的扫描器，
> 并把查询锚点人为偏移若干字节，检查能否精确找回。
> 这套自测程序依赖我们内部的 IL2CPP 元数据工具，因此不在本仓库中。

## 4. 文件编码与行尾纪律

这一节是给**改代码的人**看的。发行包里混着 `.cmd` / `.ps1` / `.ini` /
`.md`，它们的编码要求各不相同，搞错了玩家那边会直接打不开工具：

| 文件类型 | 硬要求 | 原因 |
|---|---|---|
| `*.cmd` / `*.bat` | **纯 ASCII + CRLF** | `cmd.exe` 按字节偏移解析批处理。LF 行尾叠加多字节中文会让解析位置逐行漂移，把整行劈成两半当命令执行 |
| `*.ps1` | CRLF；**含中文时必须有 UTF-8 BOM** | PowerShell 5.1 在没有 BOM 时按 ANSI 读，中文变乱码 |
| `*.ini` | UTF-8 **BOM** + CRLF | 工具与 DLL 双方都按这个约定读写 |
| `*.md` / `*.c` / `*.h` | UTF-8；行尾不限 | 不参与解析 |

因此**中文提示只写在 `installer.ps1` 里，`manage.cmd` 保持纯 ASCII**。

## 5. 发布流程

一次发布产出的东西：

```
1. 四个 DLL        d3d11.dll / mod-speedkey.dll / mod-pinattr.dll / mod-goldhand.dll
2. 安装器          installer.ps1 + manage.cmd
3. 玩家文档        使用说明.md
4. 配置源          settings.ini
5. 封面            mod/preview.png（游戏 Mod 列表封面）+ 条目根 preview.png（工坊宽封面）
6. 条目清单        mod.json（modId / name / version / minGameVersion / description）
```

### 5.1 版本号

四个模块**各自独立编号**，因为它们可以单独更新：

| 模块 | 当前 |
|---|---|
| hotkey（伞形，主版本号） | 2.9.0 |
| speedkey | 1.1.25 |
| pinattr | 1.0.14 |
| goldhand | 1.0.12 |

改版本号的位置：各模块 `.c` 里顶部的 `*_VERSION` 宏、
`installer.ps1` 的 `$ModVersion` / `$ToolVersion`、以及条目 `mod.json` 的 `version`。

### 5.2 部署三处

| 位置 | 内容 |
|---|---|
| 游戏根目录 | 4 个 DLL |
| `%USERPROFILE%\AppData\LocalLow\UserJoy\HSLR\MODS\待机快捷键\` | 全套（DLL + 工具 + 文档 + 封面） |
| `<Steam 库>\steamapps\workshop\content\4030150\<物品ID>\` | 同上（Steam 的本地同步缓存） |

第三处只是本地缓存，**线上仍需在 Steam 创意工坊后台上传**。

### 5.3 两条纪律

**① 部署时不要覆盖作者的工坊素材。**
条目里的 `mod.json` 与根目录的 `preview.png` 是作者手工维护的
（工坊描述里有大量排版与迭代说明），与构建产出的模板不同源。
`installer.ps1` 对此是「保留优先」：已有同 `modId` 的 `mod.json` 就原样不动
（`-Force` 才重生成），封面只补缺不覆盖。

**② 重新生成锚点表的时机。**
`<模块>/src/rva_anchors.h` 是从**上一次重解时的** `GameAssembly.dll`
采样出来的生成物。所以：

- 源码里增加了新的地址引用（`FN(0x…)` / `rva_of(0x…)` / `#define *_RVA 0x…`）
  → 要重新采样，把新锚点补进去；
- 官方更新了游戏、我们做了新的重解 → 要重新采样，且**必须**对着新的
  `GameAssembly.dll` 采样，否则锚点指向旧构建、`ADAPTIVE` 模式会找错。

采样工具属于我们内部的 IL2CPP 元数据工具链，不在本仓库中。
`rva_anchors.h` 是生成物但**跟着源码一起提交**，
这样本仓库不需要那套工具也能独立构建。
