# 02 · 应用模型

本文描述 Mod **运行时**长什么样：从游戏加载 `d3d11.dll` 那一刻起，
到功能可用、到每帧做事、到出错降级，完整链路。
设计动机与取舍见 `01-设计与架构.md`。

---

## 1. 一次启动的完整时序

```
游戏进程加载 d3d11.dll（走 DLL 搜索顺序，游戏目录优先于 System32）
        │
        ├─ DllMain(DLL_PROCESS_ATTACH)
        │     └─ 创建 worker 线程后立即返回
        │        （DllMain 里不能做重活：它持有 loader lock，
        │         在里面等待/加载别的 DLL 会死锁）
        │
        └─ worker 线程 ────────────────────────────────────────────────
              ①  打开日志（DLL 同目录 hslr-<name>.log，每次启动覆盖）
              ②  把本 DLL 的实际路径写进日志
              ③  load_satellites()   ← 先装卸载，见 §3
              ④  config_setup()      ← 读 ini；不存在则写一份默认的
              ⑤  <mod>_fallback_init()  ← modId 自愈白名单
              ⑥  known_build()       ← GameAssembly.dll 的 SHA256 三态判定
                    └ -1 → 记日志、退出（真的出问题了）
              ⑦  等 GameAssembly.dll 被加载（最多 600 × 100 ms = 60 s）
              ⑧  rva_reloc_configure(伞形 ini) + rva_reloc_init(build_ok == 1)
              ⑨  check_fingerprints()  ← 闸门；不过 → 记日志、退出
              ⑩  il2cpp_ready()
              ⑪  MH_Initialize()
              ⑫  安装 hook（按 NATIVE / ADAPTIVE 分两条路径，见 §5）
              ⑬  LogicMgr 实例捕获 hook（非致命）
              ⑭  写配置摘要日志，开始等游戏自己每帧调用我们的钩子
```

**顺序上的两个刻意安排**：

- **③ 在 ⑨ 之前**。三个卫星的指纹表各不相同，伞形自己的校验不该连坐卫星
  能通过的那份。装载结果只写日志，不影响后续流程。
- **⑧ 在 ⑫ 之前**。`rva_of()` 决定了后面每一个地址怎么算，
  必须在**任何** `FN()` / `addhook()` 之前就绪。

## 2. 线程模型

整个 Mod 只额外起**一个**线程（就是上面那个 worker），而且它只做「等 + 初始化」，
初始化完成后就退出。**所有持续性的工作都在游戏主线程上做**。

| 阶段 | 线程 |
|---|---|
| `DllMain` | 游戏加载线程（不做事，只起 worker） |
| 初始化 ①~⑭ | worker 线程 |
| 挂载后的所有工作 | **游戏主线程**（由输入钩驱动） |

这样安排的理由是 Unity：`GameObject` / `Transform` / UI 组件的状态
都只能在主线程访问，从别的线程碰它们是未定义行为。
把一切收束到「游戏每帧自己调我们」这一条路径上，就天然满足约束，
也**不需要任何锁**。

跨 DLL 的状态（伞形 ↔ 卫星）通过两条通道：

1. **导出函数 + 函数指针表**：卫星 `__declspec(dllexport)` 出
   `*_frame_tick` / `*_input_focus`，伞形用 `GetProcAddress` 拿指针，
   存进 `g_sat_ticks[]` 表里每帧遍历调用。
2. **全局值**：伞形读到的「游戏内 Mod 开关状态」「焦点状态」通过
   参数传给卫星的 tick（`sk_frame_tick()` 无参、`*_input_focus(bool)` 有参）。

因为都在同一线程，这些交互不需要原子操作 —— **单一写入者 + 同线程读取**。

## 3. 卫星装载

`load_satellites()`（伞形）做的事，按顺序：

```
对 (文件名, 标签) 列表里的每一项：
  ├ path_for(path, "mod-speedkey.dll")     ← 拼成「本 DLL 所在目录\名字」
  ├ 文件不存在 → 记日志「feature not bundled」，跳过（不算错误）
  ├ LoadLibraryW(path)
  │    └ 失败 → 记日志「load FAILED err=N」，跳过
  └ GetProcAddress 拿 tick / focus 两个导出
       └ 拿到几个记几个，缺失的记「MISSING」
最后统计「已接线的 tick 数」写进日志
```

**永不解载**。`LoadLibraryW` 计入引用计数，进程生命周期内不调 `FreeLibrary` ——
卸载会撤走卫星已经装好的 MinHook 跳板，之后跳板就是野指针。

日志里那行 `Satellite frame ticks wired: N/3` 是刻意加的：
这个数字对不上卫星数量，就说明「只装了指针没接驱动表」——
历史上金之手哑火过一次，形态就是这个。

## 4. 每帧链路

游戏主线程每帧调用 `NewInputManager$$Update`，落到我们的 `hk_input_update`：

```
hk_input_update()
 ├ config_maybe_reload()          ← 见 §6
 ├ keys_poll()                    ← 读物理键状态（只读，不接管、不屏蔽）
 ├ 菜单门禁判定
 │    └ 条件都满足 → 调用游戏自己的 UIButtonEx.InvokeClick（等同玩家亲手点）
 ├ 读游戏内 Mod 开关（mod_profile.json）
 └ drive_satellites()
      ├ sk_frame_tick()           ← 战斗倍速
      ├ pa_frame_tick()           ← 属性道具稳定加值
      └ gh_frame_tick()           ← 金之手
```

另一个钩子 `hk_input_focus` 处理切出/切回：
维护「游戏窗口是否在前台」，不前台时不响应热键；
并把焦点变化转发给三个卫星的 `*_input_focus(bool)`。

**卫星的 tick 只做「当帧要不要动」的判断**，真正的功能实现挂在自己的
MinHook 钩子上（例如 pinattr 钩 `UsePlayerBagItem` /
`UseStorageItem` / `AddByType` / `CastOnByItem`，goldhand 钩
`StageManager$$GetAtkShowDatas`）。这些钩子是功能私有的，不参与上面的链路。

### 菜单门禁

`hotkey/src/menu.h` 里的门禁是一串「必须同时成立」的条件，任一不成立就不派发：

- 游戏窗口在前台
- 游戏内该 Mod 条目为「已启用」且未被标记不兼容
- 当前确实处于角色行动菜单，且菜单**已经确认可操作**
  （`LogicMgr` 实例已捕获、`ModUIInputBlocker.get_IsBlocking` 为假）
- 目标按钮当前可点、不在冷却中
- 配置文件里没有要求「必须无修饰键」（`require_no_modifier`）

**刻意设计**：菜单外按键没有反应。这是刻意的，避免误触。

## 5. 挂钩安装的两条路径

`rva_reloc_init()` 之后 `rva_mode` 已知，挂钩策略随之分叉：

| 模式 | 策略 |
|---|---|
| `NATIVE` | 三条钩子（`Update` / `OnApplicationFocus` / `AMenu.show`）**任一失败即整体放弃**，恢复 v2.8.0 的原始行为 |
| `ADAPTIVE` | **单点降级**：`Update` 是卫星唯一的驱动源，缺它就没意义 → 停；其余两个缺哪个只损失对应能力，记日志继续 |

`LogicMgr$$Update` 的实例捕获钩**在两个模式下都是非致命**的：
失败只退化菜单门禁的一环（少一个判定条件），不影响热键本体。
注意它是在 `MH_EnableHook(MH_ALL_HOOKS)` **之后**创建的，
所以必须显式 `MH_EnableHook` 单独打开。

## 6. 配置热重载模型

四份 ini 都是**改完保存即生效**，不用重启游戏、不用重装。

实现方式统一是 **mtime 比对**（`GetFileAttributesExW` → `ftLastWriteTime`）：

```
每帧：
  取 ini 的 ftLastWriteTime
  与上次记录的时间戳相同 → 直接返回（绝大多数帧走这条，零开销）
  不同 → 解析到临时结构 → 解析成功才整体替换当前配置
                        → 解析失败保留旧配置并记日志
```

三条纪律：

1. **解析成功才替换**。半解析的配置绝不生效 —— 避免玩家改到一半存盘时
   功能进入不可预期的状态。
2. **解析失败保留旧值**。日志写「reload failed; keeping the previous bindings」。
3. **缺键 = 用默认**，不是错误。老配置文件不写新键时行为不变。

伞形的 `[features]` 段（分功能总开关）被三个卫星**跨文件读取**：
卫星读的是伞形那份 `hslr-wait-hotkey.ini`，同样走 mtime 热重载。
文件缺失或键缺失一律**视为开**（保持旧行为）。

## 7. 失败与降级矩阵

| 失败点 | 影响范围 | 处理 |
|---|---|---|
| `GameAssembly.dll` 读不到 | 全部 | 停（这是真的安装错了） |
| SHA256 不在白名单 | 全部 | 不停 —— 转 `ADAPTIVE` 重定位 |
| 锚点重定位失败（个别点） | 依赖该点的功能 | 单点降级，记 `reloc FAIL` |
| 指纹/锚点闸门不过 | 该模块 | 停该模块，记日志 |
| 卫星 DLL 缺失 | 该功能 | 跳过，记「not bundled」 |
| 卫星 `GetProcAddress` 拿不到 | 该功能 | 记「MISSING」，继续 |
| 菜单元数据解析失败 | 菜单热键 | 只退化菜单门（`ap_runtime_ok` / `wk_logicmgr_hook_ok` 为假） |
| `MinHook` 初始化失败 | 全部 | 停 |
| `LogicMgr` 捕获钩失败 | 菜单门禁的一个条件 | 记日志，继续 |

核心不变量：

> **被放行的功能，其每个地址都通过了校验；失败的锚点只会降级依赖它的功能，
> 永不拿出 0 地址去调用。**

这条不变量在两处强制：`rva_of()` 对失败锚点返回 `0`，
各模块的模块级闸门在 `*_frame_tick()` 首行拦截。
goldhand 更严一层：`kill_apply()` 里解析写点地址失败就直接 `return`（fail-safe）。

## 8. 日志与排障入口

| 位置 | 内容 |
|---|---|
| `<游戏根目录>\hslr-*.log` | 四个模块各自的日志（UTF-8，带毫秒时间戳） |
| `%LOCALAPPDATA%\Temp\UserJoy\HSLR\crash\crash-*.txt` | 游戏自身崩溃记录 |
| `%LOCALAPPDATA%\Temp\UserJoy\HSLR\breadcrumb.json` | 游戏给的阶段提示（`phase` / `inBattle`） |

游戏根日志的第一屏就有诊断信息：

```
[1234] HSLR Wait Hotkey + ... 2.9.0; umbrella d3d11.dll; game 2.2.4 / build 25767968
[1236] Mod DLL path: F:\...\幻世錄 Remake\d3d11.dll     ← 装错位置时一眼看出
[1240] GameAssembly SHA256 <64位十六进制>
[1241] reloc: NATIVE (build known; 45 anchors used as recorded, zero scan)
```

**崩溃的第一现场**是 `crash-*.txt`：如果里面只有 init 一行，说明是启动即崩溃
（典型的「装错了地址」形态），配合 `breadcrumb.json` 判断崩溃发生在哪个阶段。

`ADAPTIVE` 模式下日志会写逐点结果：

```
reloc: ADAPTIVE engine; 45 anchors; window=0x40000; stale-anchor offset=+0
reloc: 43/45 anchors relocated; 2 point(s) disabled; total candidate hits=57
```

## 9. 跨进程/跨设备边界

明确不做的事，同样重要：

- **不写注册表**。所有配置在 ini 里。卸载 = 删文件。
- **不碰存档**。存档是 ECC 加密的（游戏自己读写的格式），
  任何功能都在内存里做，不落盘、不改文件。
- **不联网、不起外部进程、不注入其他进程**。
- **不修改游戏任何原文件**。代理 DLL 是新增文件；卸载删掉即可。
- **不接管或屏蔽键盘输入**。只**读**物理键状态，按键照样传给游戏。
