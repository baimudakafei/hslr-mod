# pinattr — 属性道具稳定加值（`mod-pinattr.dll`）

**卫星模块**。由伞形 `d3d11.dll` 在启动时 `LoadLibraryW` 进来，
每帧调用它导出的 `pa_frame_tick()`。

```
伞形 d3d11.dll ──LoadLibraryW──► mod-pinattr.dll
               ──每帧调用─────► pa_frame_tick()
               ──焦点变化─────► pa_input_focus(bool)
```

## 做什么

使用「力之源 / 禦之源 / 魔之源 / 速之源」和四维之魂、霸之魂这类属性提升道具时，
游戏原本会随机加值（例如力之源随机 +1~5）。因为游戏可以随时存档读档，
玩家为了刷满值往往要反复 SL —— 随机在这里只增加操作负担。

本模块把这些道具的加值**固定为各自随机范围的上限**，一次吃到满。

**绝不误伤**：只影响配置里列出的道具。回血药、装备词条、五抗之源
（本就是固定 +1）、聖之魂以及其他一切随机效果都保持原样。
这靠两道闸门保证 —— 道具 ID 白名单 `pin_items`，
加上属性类型白名单 `attr_types`（**刻意不含 HP**：回血药走同一段代码，
把 HP 加进去会让「回血」也变成固定值）。

## 源码

| 文件 | 作用 |
|---|---|
| `pinattr.c` | 全部实现：配置、四个游戏函数挂钩、钳值逻辑 |
| `config.h` | ini 解析 + 默认配置生成 |
| `fingerprints.h` | 一致性指纹表 + 调用点字节校验 |
| `rva_anchors.h` | 生成物：运行时重定位锚点表 |

`../shared/` 下为四模块共用代码。

## 挂钩点

挂在道具使用的四个入口上，让「提示文字」与「实际落档」来自同一份钳过的值
（否则会出现界面显示 +3、实际加 +5 之类的错位）：

| 目标 | 用途 |
|---|---|
| `UsePlayerBagItem` | 从玩家背包使用道具 |
| `UseStorageItem` | 从仓库使用道具 |
| `FightAttr$$AddByType` | 属性累加 |
| `CastOnByItem` | 道具对角色生效 |

另外对若干**调用点**做 5 字节 `call` 指令的字节校验（fail-closed）：
调用点不在原样位置时直接停用，避免闸门失效。

## 配置

完整说明见 `../docs/04-配置说明-完整.md` 第 3 节。核心一条：

```ini
[options]
pin_items = 224:5,225:5,226:5,227:5,280:15,281:15,282:15,283:15,290:10
```

格式 `道具ID:数值`，逗号分隔。只有列出的道具会被干预。

伞形 `hslr-wait-hotkey.ini` 的 `[features] pinattr = 0` 可整体关掉本模块。
